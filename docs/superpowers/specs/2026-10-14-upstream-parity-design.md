# Upstream parity, downloads and Lora Manager sidecars — design

Date: 2026-10-14. Status: agreed with the user in conversation; implemented by three plans:

| Plan | File | Ships |
|---|---|---|
| A — foundations | `docs/superpowers/plans/2026-10-14-a-foundations.md` | matching, wrong-folder flag, XSS fix, off-loop routes, settings + tokens |
| B — downloads | `docs/superpowers/plans/2026-10-14-b-downloads-lookups-sidecars.md` | sources, background lookups, downloads, HF engine, Lora Manager sidecars |
| C — workflow UI | `docs/superpowers/plans/2026-10-14-c-workflow-ui.md` | locate into subgraphs, All models swap, load-time notice, Export tab, docs |

Each plan ships working software on its own; B needs A's settings module, C's Export tab needs B's source chain.

## What the user asked for

1. Everything upstream (kianxyzw/comfyui-model-linker v1.2.3, commit `bec5c80`) has that this fork lacks, most important first.
2. **Reverse the "no downloads" decision**: CivitAI and HuggingFace downloads, CivArchive and CivitAI hash lookups.
3. **Online lookups run on their own, asynchronously.** They must never block the user or ComfyUI. If the dialog is closed while they run, the results are kept and shown quietly the next time it opens.
4. **Model info written in Lora Manager's format** (`<stem>.metadata.json` + preview image) so the user no longer fetches it by hand in Lora Manager.

## Decisions

- **Porting, not merging.** Upstream code is copied file-by-file with `git show bec5c80:<path>` (fallback: `gh api repos/kianxyzw/comfyui-model-linker/contents/<path>?ref=bec5c80 -H "Accept: application/vnd.github.raw"`) and then edited. No upstream remote, merge or rebase — see CLAUDE.md.
- **Upstream bugs are not ported.** Its `/download` has no path-traversal guard; HF routing uses a substring host test; `/search` runs on the event loop and returns partial matches; analysis sends a HEAD request to any URL a shared workflow names; bulk download has no concurrency cap; its frontend reads `data.huggingface?.[0]` from a dict so HF/CivitAI results never render; the Missing-Models popup injection throws `btnContainer` ReferenceError. Each is fixed or avoided by design in Plan B/C.
- **Background lookups** (Plan B, Task 3): `/analyze` stays local and fast. After it answers, missing models without a cached result are queued to one background worker thread. Results persist in `data/lookups.json`, keyed by SHA-256 when the workflow carries one, else `canonical_category:normalized_name`. Negative results expire after 24 hours (the source modules swallow network errors and return None, so an outage looks like "not found" — a short expiry keeps that from hiding a model for long), and a "Search again" button bypasses the store. Models that already have a perfect local match are never looked up. `/analyze` attaches cached results immediately, so a reopened dialog shows them without waiting. The frontend polls `/model_linker/lookups` only while results are pending, and updates cards **in place** by `refSlot()` — never re-rendering the list, which would drop queued selections. A setting `auto_lookup` (default **on**) turns this off; the settings dialog says why someone would (filenames go to HuggingFace and CivitAI).
- **Downloads** run in a server-side queue with **two** workers, so they continue when the dialog closes. Destination = first directory registered for the category; filename reduced to a basename; the final path must pass `reveal._is_within` against that directory. `https` only. Free disk space is checked against the expected size before starting. Files stream to `<dest>.part` and are `os.replace`d into place. HuggingFace URLs (decided by `settings.provider_for_url`, a real host check) use upstream's `huggingface_hub` engine in a subprocess; everything else uses the streaming engine.
- **Lora Manager sidecars** (Plan B, Task 6): after every completed download, hash the bytes on disk (never trust a claimed hash — Lora Manager trusts a non-empty `sha256` forever), look the hash up on CivitAI `model-versions/by-hash`, enrich with `GET /models/{modelId}` (tags, description, creator, licence flags — Lora Manager never re-fetches once `civitai.id` is set), strip `images[].meta.comfy`, write `<stem>.metadata.json` atomically and the preview as `<stem>.<url-ext>` from the `/width=450,optimized=true/` CDN rendition. CivitAI not knowing the hash → write the minimal valid sidecar and ask Lora Manager to fetch (its own chain includes CivArchive). Finally, best-effort `GET /api/lm/{prefix}/scan` against the local server so Lora Manager indexes the new file. Format reference: Lora Manager v1.2.5, `py/utils/models.py:72-444` and `docs/metadata-json-schema.md`. **Lora Manager is GPL-3.0 and this extension is MIT: implement the file format from its documentation; copy none of its code.**
- **Similar-model search** (Plan B, Task 8; decided 2026-10-15). On request only ("🔎 Search similar"), every model file from the bundled index, ComfyUI-Manager's list, HuggingFace repos and CivitAI search is scored with the banded matcher; different sizes/generations are labelled "different model". A chosen candidate is saved under **its own filename**, never the workflow's, so a near match cannot pass for the exact file; it then shows up as an ordinary fuzzy match to select. Similar results never enter `download_source`, so background lookups and "Download all found" only ever fetch exact or hash matches.
- **Filling empty Lora Manager info from HuggingFace** (Plan B, Task 9; asked for on 2026-10-15). Lora Manager can already turn a HuggingFace model card into sidecar data (README → HTML description, example images, `instance_prompt` trigger words, preview, `metadata_source: "source:huggingface"`), and with its LLM also base model and tags — but only for a model already linked to a repo. This extension supplies the missing step: identifying the repo **by SHA-256** (recorded link → bundled index → name search verified file-by-file against HuggingFace's published LFS hashes; a name alone never links), then calling Lora Manager's own routes to link and hydrate, so the output is exactly its format and its cache stays consistent. A server-side job with a persisted report (`data/lm-backfill.json`), started from ⚙ Settings; AI enrichment is opt-in. Lora Manager's hydration clears trigger words when the README has none; they are saved before and merged back after.
- **No DOM scraping.** Upstream injects a button into ComfyUI's Missing Models popup with a document-wide `MutationObserver` keyed on English text; CLAUDE.md forbids that. Instead the `afterConfigureGraph` extension hook analyzes the loaded workflow in the background (which also starts lookups) and shows a toast with the missing count; an opt-in setting opens the dialog automatically.
- **`requests` becomes a declared dependency** (already installed: 2.34.2). Download/lookup routes register only if it imports, so the extension still loads without it. `huggingface_hub` (installed 1.33.0) is optional; without it, or below 1.1, HuggingFace files use the streaming engine.
- **Python floor** goes from 3.8 to 3.9 for `asyncio.to_thread`.

## Lora Manager sidecar contract (v1.2.5)

Required — a sidecar missing any of these makes Lora Manager **skip the model** (`metadata_manager.py:55-57`): `file_name` (stem), `model_name`, `file_path` (absolute, `/` separators), `size` (int bytes), `modified` (float epoch: when imported), `sha256` (lowercase hex), `base_model`, `preview_url` (absolute `/` path or `""`).

Written as well: `preview_nsfw_level` (int), `notes` `""`, `from_civitai` (bool), `civitai` (dict), `tags` (list), `modelDescription` (str), `civitai_deleted` false, `favorite` false, `exclude` false, `db_checked` false, `skip_metadata_refresh` false, `metadata_source` (`"civitai_api"` or `null`), `last_checked_at` (float), `hash_status` `"completed"`, `autov3` (12 lowercase hex from the matching `files[].hashes.AutoV3`, JSON `null` if CivitAI had none; key omitted when nothing was checked). LoRA adds `usage_tips: "{}"`. Checkpoints/diffusion models add `sub_type` `"checkpoint"`/`"diffusion_model"`; embeddings `sub_type: "embedding"`; other types `sub_type` from `vae|upscaler|text_encoder|clip_vision|controlnet`. **No `model_type` key** (the schema doc says `model_type`; the v1.2.5 code reads `sub_type`).

`base_model` = Lora Manager's `determine_base_model(civitai.baseModel)`: `"Unknown"` when empty, else the first case-insensitive **substring** hit in `sd_1.5→SD 1.5, sd-v1-5→SD 1.5, sd-v2-1→SD 2.1, sdxl→SDXL 1.0, sd-v2→SD 2.0, flux1→Flux.1 D, flux.1 d→Flux.1 D, illustrious→Illustrious, il→Illustrious, pony→Pony, Hunyuan Video→Hunyuan Video`, else the string unchanged. Copied verbatim, including its quirks (`"SDXL Lightning"` → `"SDXL 1.0"`).

Category → Lora Manager route prefix: `loras→loras`; `checkpoints→checkpoints` (sub_type checkpoint); `diffusion_models`/`unet→checkpoints` (diffusion_model); `embeddings→embeddings`; `vae`, `upscale_models`, `text_encoders`/`clip`, `clip_vision`, `controlnet→other`. Any other category gets no sidecar.

## Out of scope

- Hash lookups through ComfyUI's Assets API (needs `--enable-assets`; separate backlog item).
- Re-encoding previews (no Pillow dependency): the CDN rendition is saved as served.
- Centralized sidecar storage mode in Lora Manager (`sidecar_storage_mode: "centralized"`): the user runs the default `alongside` mode. The writer checks `settings.json` of Lora Manager and skips writing, with a log line, when centralized mode is on.
